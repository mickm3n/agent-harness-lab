# AI 開發資安檢核表

> **公司規定優先。** 本表是「沒有現成規範時的起點」與「補漏的下限」，不取代既有的資安政策與稽核要求。課堂填完後，請對齊你們部門現行的政策。

## 資安看三個地方：讀進什麼、能做什麼、交出什麼

| 地方 | 檢查項 | 人工 | agent |
|---|---|---|---|
| **進去什麼** | 1. agent 讀過 `.env` 或 `config/production.yaml` 嗎？讀到的機密有沒有被遮掉？ | | |
| | 2. Claude Code 走的是公司核可的端點（官方、核可的雲端供應商或公司 gateway），還是來路不明的中轉 API？看設定，不看 diff | | |
| **它能做什麼** | 3. agent 用了哪些工具？有沒有繞過 deny（例如 `grep -r`、子行程、`git show`）？ | | |
| | 4. 它讀進去的檔案和工具輸出（issue、README、註解）有沒有夾帶指令？它有沒有照做？（prompt injection） | | |
| **產出什麼** | 5. diff 有沒有新增依賴？套件真的存在嗎？授權相容嗎？ | | |
| | 6. 它宣稱跑過的測試真的跑過嗎？引用的 API、參數、行為真的存在嗎？ | | |
| | 7. diff 有碰到權限、金流、個資、資料庫嗎？有的話誰復核？ | | |
| | 8. 對照下方五種漏洞長相，自己的 diff 和周邊既有程式碼有沒有中？ | | |

**兩欄的用法**：同一個 diff 分別用「人工對照本表」「請 agent 審 diff」各跑一次，在對應欄打勾表示「這種方法抓到了」。重點不是抓幾個，是**兩欄都沒打勾的項目**：讀了什麼、送出了什麼不在 diff 上，人工與 agent 都審不到，只能靠機制擋（deny、sandbox、managed settings）。官方另有 security-guidance plugin 會在 agent 改檔時自動提醒，可以回去自己試。

## AI 生成程式碼常見的漏洞長相（對照自己的 diff）

- 缺少輸入驗證
- 權限判斷漏一條分支
- 硬寫的預設值與金鑰
- 錯誤訊息洩漏內部結構
- 只處理樂觀路徑的例外處理
